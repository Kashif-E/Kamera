# Migrating from 1.x to 2.0

2.0 replaces the 1.x camera API. `CameraController` and the `Ready.controller` it hung off are gone:
one `CameraKStateHolder` owns the camera, reports it as `StateFlow`s and runs suspend commands that
return a `CameraKResult`. Most 1.x calls that have a direct replacement still compile far enough to
show an error with a quick fix (an ERROR-level `@Deprecated` with `ReplaceWith`); use it, then work
through the sections below. Those hints are removed in 2.1. Code compiled against 1.x that reaches
a hint throws `UnsupportedOperationException("Removed in CameraK 2.0; see the migration guide")`.

The sections follow the order you will meet the changes in.

## 1. Dependencies

| 1.x | 2.0 |
|-----|-----|
| `camerak` | `camerak`, unchanged: the camera with its Compose UI. It exports `camerak-core`. |
| | `camerak-core`: the camera without Compose, for apps that do not use Compose |
| | `camerak-testing`: the fake camera, for test source sets only |
| | `camerak-bom`: pins every CameraK artifact to one version |
| `image_saver_plugin` | `camerak-media-saver` |
| `qr_scanner_plugin` | `camerak-qr-scanner` |
| `ocr_plugin` | `camerak-ocr` |
| `analyzer_plugin` | `camerak-analyzer` |
| `video_recorder_plugin` | none: recording is in the core (section 8) |

All are in `io.github.kashif-mehmood-km`. Each 1.x plugin id is published at 2.0 as a relocation
POM pointing at the new id, so an old declaration still resolves (Gradle reports the relocation),
but switch to the new ids: 2.1 stops publishing the relocations. Only the root ids relocate; a
build that names a per-target id (`ocr_plugin-android`, `-desktop`, `-iosarm64`, or 1.x's Intel-simulator
id) must rewrite it. `video_recorder_plugin` has no successor and no relocation.

```kotlin
kotlin {
    sourceSets {
        commonMain.dependencies {
            implementation("io.github.kashif-mehmood-km:camerak:2.0")
            implementation("io.github.kashif-mehmood-km:camerak-qr-scanner:2.0")   // was qr_scanner_plugin
        }
        commonTest.dependencies {
            implementation("io.github.kashif-mehmood-km:camerak-testing:2.0")
        }
    }
}
```

**Platform minimums.** iOS 16.0 is the minimum: set the app's deployment target to 16.0 or later.
On an older system the camera reports `Error(Unsupported(PLATFORM_VERSION))` instead of opening.
There are no Intel-simulator artifacts. Android needs `minSdk = 23`. Desktop apps add the
bytedeco natives for the platforms they ship (see [Installation](../getting-started/installation.md#desktop-jvm)).

**Compose and Kermit.** `camerak-core` exports no Compose and no Kermit (`co.touchlab:kermit`); an
app that uses Kermit declares it.

**CameraX.** On Android, `camerak-core` exports only `androidx.camera:camera-core`. It still uses
`camera-camera2`, `camera-lifecycle` and `camera-video`, but no longer exports them, and it no
longer depends on `camera-view` at all. An app that imports CameraX classes itself (`PreviewView`,
`ProcessCameraProvider`, `Recorder`, `Camera2Interop`) declares the CameraX artifacts it uses.

## 2. Packages

Two plugin packages changed only in letter case. Rewrite the imports; there are no aliases at the
old names, because the two packages would share a directory on a case-insensitive disk:

| 1.x import | 2.0 import |
|------------|------------|
| `com.kashif.ocrPlugin.*` | `com.kashif.ocrplugin.*` |
| `com.kashif.analyzerPlugin.*` | `com.kashif.analyzerplugin.*` |

The image saver moved and was renamed. Its old names stay as ERROR-level hints with a quick fix
until 2.1:

| 1.x | 2.0 |
|-----|-----|
| `com.kashif.imagesaverplugin` | `com.kashif.mediasaverplugin` |
| `ImageSaverPlugin` | `MediaSaverPlugin` |
| `rememberImageSaverPlugin(config)` | `rememberMediaSaverPlugin(config)` |
| `ImageSaverConfig` | `MediaSaverConfig { ... }` |

`com.kashif.qrscannerplugin` and `com.kashif.cameraK` keep their names.

**The OCR model on desktop.** A packaged `eng.traineddata` moves from
`com/kashif/ocrPlugin/tessdata/eng.traineddata` to `com/kashif/ocrplugin/tessdata/eng.traineddata`
on the classpath. 2.0 still reads the 1.x path when the new one has no model, and logs a warning
to move it.

## 3. The entry point

```kotlin
// 1.x
val cameraState by rememberCameraKState(config) { holder -> holder.attachPlugin(scanner) }

// 2.0
val holder = rememberCameraKStateHolder(config, plugins = listOf(scanner))
val state by holder.cameraState.collectAsStateWithLifecycle()
```

The holder survives rotation: it lives in a ViewModel of the screen, with its plugins and any
recording, and closes when the screen goes away. It starts and stops with the screen's lifecycle
and re-checks the permission on resume. Pass plugins as a list instead of attaching them in a
callback; a plugin that reads frames then gets them from the first bind.

For the screen: `CameraKScreen(cameraState = ...)` becomes `CameraKScreen(holder)`, with `loading`,
`error` and `content` slots, and `CameraPreviewView(controller)` becomes `CameraPreview(holder)`.
`DefaultLoadingScreen` and `DefaultErrorScreen` are gone: the slots draw nothing unless you pass
your own. `LocalCameraKStateHolder` is gone: pass the holder.

Without Compose: `CameraKStateHolder(config, CameraKPlatformContext(context), plugins)`, driven with
`start()`, `stop()` and `close()`, or with `bindToLifecycle(lifecycle)`.

## 4. States

| 1.x | 2.0 |
|-----|-----|
| `Initializing` | `Idle` (not started) and `Starting` (opening) |
| `Ready(controller, uiState)` | `Ready`, a data object; commands are on the holder, state in `holder.uiState` |
| `Error(exception, message, isRetryable)` | `Error(error: CameraKError)`, with `isRetryable` |
| | `Interrupted(reason)`: the system holds the camera (a call, multitasking). Keep the controls reachable and show a paused overlay |
| | `Closed`: after `close()`, for good |

`CameraKState` is closed, so a `when` over it is exhaustive without `else`. `CameraKEvent` is open
and needs an `else`. The holder emits only two events: `RecordingEnded` and `PluginFailed`.

## 5. Commands

Every command is a suspend function on the holder that returns `CameraKResult<T>`:

```kotlin
// 1.x
when (val result = controller.takePictureToFile()) {
    is ImageCaptureResult.SuccessWithFile -> show(result.filePath)
    is ImageCaptureResult.Error -> showError(result.exception)
}

// 2.0
scope.launch {
    holder.capture()
        .onSuccess { image -> show(image.path) }
        .onFailure { error -> showError(error) }
}
```

| 1.x | 2.0 |
|-----|-----|
| `controller.takePictureToFile()`, `takePicture()` | `holder.capture()`: `CameraKResult<CapturedImage>` |
| `holder.captureImage()` and the `ImageCaptured` event | `holder.capture()`, or collect `holder.captures` |
| `toggleFlashMode()` | `cycleFlashMode()` |
| `toggleTorchMode()` | `toggleTorch()` |
| `toggleCameraLens()` | `toggleLens()` |
| `controller.setZoom(z)`, `setFlashMode(m)`, `setTorchMode(m)` | the same names on the holder, returning what the platform applied |
| `setPreferredCameraDeviceType(type)` | `selectCamera(lens, type)` or `selectCamera(id)` |
| `getCameraCapabilities()` | `holder.capabilities.value` |
| `shutdown()` | `close()` |

`cycleFlashMode`, `toggleTorch` and `toggleLens` are extensions in `com.kashif.cameraK.controls`.
Before the camera is Ready a command returns `Failure(NotReady)`, and after `close()`
`Failure(Closed)`. A capture is always a file in app-owned storage; `ImageCaptureResult.Success`
with bytes is gone.

## 6. State reads

| 1.x | 2.0 |
|-----|-----|
| `state.uiState` | `holder.uiState` |
| `uiState.zoomLevel`, `uiState.maxZoom`, `controller.getZoom()` | `holder.zoom`: `ratio`, `minRatio`, `maxRatio` |
| `uiState.isRecording`, `isPaused`, `recordingDurationMs` | `holder.recordingState`, and `rememberRecordingElapsed(holder)` for a timer |
| `uiState.lastError` | `cameraState`'s `Error`, and each command's `Failure` |
| `uiState.imageFormat`, `qualityPrioritization` | the `CameraConfiguration` you passed |

`uiState` now reports what the platform did, not what was asked: after `setTorchMode(ON)` the torch
reads ON once the device turned it on.

## 7. Errors

`CameraKState.Error.exception` and `message` become `error: CameraKError`, a closed hierarchy whose
every error keeps the platform's `cause` and says through `isRetryable` whether trying again can
succeed.

| 1.x situation | 2.0 error |
|---------------|-----------|
| The camera permission is missing | `Permission(CAMERA, status)`; `needsSettings` when only the system settings can grant it |
| Another app holds the camera | `CameraInUse` |
| No camera for the lens | `NoCamera(lens)` |
| The camera was disconnected or failed while running | `Disconnected`, `Hardware(platformCode)` |
| A capture or recording could not be written | `Storage(kind, keptFilePath)`; `keptFilePath` names a file the platform kept |
| A feature the device lacks | `Unsupported(feature)` |
| Desktop natives missing | `NativeLibraryMissing(platform)` |
| An operation that did not answer | `Timeout(operation)` |
| Anything unexpected | `Internal(cause)` |

Show an Open Settings button when `error is CameraKError.Permission && error.needsSettings`, and
call `holder.retry()` from `Error`.

## 8. Recording

`VideoRecorderPlugin` and its artifact are gone; the holder records:

```kotlin
// 1.x
videoRecorderPlugin.startRecording(outputDirectory)

// 2.0
scope.launch { holder.startRecording(VideoConfiguration { outputDirectory = dir }) }
scope.launch { holder.stopRecording().onSuccess { video -> show(video.path) } }
```

| 1.x | 2.0 |
|-----|-----|
| `RecordingStarted` event | `startRecording` returns once the platform confirms it |
| `RecordingStopped`, `RecordingFailed` events | `stopRecording()`'s `CameraKResult<RecordedVideo>`, or `RecordingEnded` for an end you did not ask for |
| `RecordingMaxDurationReached` | `RecordingEnded` with reason `MAX_DURATION` |
| `VideoConfiguration(maxDurationMs = 0)` | `VideoConfiguration { maxDuration = null }`; `maxDuration` is a `Duration?` |
| `maxFileSizeBytes = 0` | `maxFileSizeBytes = null` |
| `enableAudio = true` by default | `enableAudio = false` by default; with `true` the microphone permission is required, and desktop returns `Unsupported(AUDIO)` |

A lens switch during a recording returns `Busy(LENS)` and changes nothing.

## 9. Storage and the gallery

1.x wrote captures to the gallery when `CameraConfiguration.directory` was `PICTURES` or `DCIM`.
2.0 writes every capture and recording to app-owned storage (`outputDirectory`, else
`filesDir/CameraK`, `Documents/CameraK` or `~/Documents/CameraK`), and only the media saver writes
the gallery:

```kotlin
val saver = rememberMediaSaverPlugin(MediaSaverConfig { destination = GalleryDestination.PICTURES })
val holder = rememberCameraKStateHolder(plugins = listOf(saver))

scope.launch { holder.capture().onSuccess { image -> saver.save(image) } }
```

| 1.x | 2.0 |
|-----|-----|
| `Directory.PICTURES`, `DCIM`, `DOCUMENTS` | `GalleryDestination.PICTURES`, `DCIM`, `DOCUMENTS` in `MediaSaverConfig` |
| `ImageSaverConfig(isAutoSave = true, customFolderName = "x")` | `MediaSaverConfig { autoSave = true; folderName = "x" }` |
| `saveImage(bytes)`, `save(bytes, name)` | `save(image: CapturedImage, name)`, `save(video: RecordedVideo, name)` |
| `getByteArrayFrom(path)`, `readBytes(path)` | `readBytes(saved: SavedImage)` |

`SavedImage.asset` is the gallery's handle: the content URI on Android, the Photos local identifier
on iOS, the file path on desktop. Existing files are not moved. On Android, captures move from
`getExternalFilesDir(null)/CameraK` and the public folders to internal `filesDir/CameraK`.

App-owned storage is backed up: iCloud and device backups on iOS, Auto Backup on Android. To keep
captures out of backups, see [Backups](../getting-started/configuration.md#backups).

## 10. Plugins

Each plugin has the same shape: a configuration DSL, `results` (a `Flow`), `status`
(`StateFlow<PluginStatus>`), and `pause()` and `resume()` for the frame readers. Handles became
`FrameRegistration`.

| Plugin | 1.x | 2.0 |
|--------|-----|-----|
| QR | `getQrCodeFlow()`, `QRCodeScanned` event, `ScannerHandle`, `startScanning`, `pauseScanning`, `resumeScanning` | `results: Flow<Barcode>`, `pause()`, `resume()`; `QRScannerConfig { formats; region; dedupeWindow; maxFps }` |
| OCR | `textFlow`, `ocrFlow`, `TextRecognized` event, `extractTextFromBitmap`, `startRecognition`, `stopRecognition` | `results: Flow<RecognizedText>`, `recognize(image: CapturedImage)`, `pause()`, `resume()`; `OcrConfig { maxFps; region; level; tessdataPath }` |
| Analyzer | `getAnalyzerFlow()`, `AnalyzerHandle`, `startAnalyzer`, `stopAnalyzer` | `results: Flow<EncodedFrame>`, `pause()`, `resume()`; `AnalyzerConfig { maxFps; maxDimension; jpegQuality }` |
| Saver | see section 9 | |

Every plugin's coroutine-scope constructor and `attachToStateHolder` are gone: pass the plugin to
the holder. For frames of your own, register on `holder.frames`:

```kotlin
val registration = holder.frames.register(FrameSpec(maxFps = 10f)) { frame -> analyze(frame) }
// later
registration.close()
```

**Writing a plugin.** `CameraKPlugin.onAttach(stateHolder: CameraKStateHolder)` becomes
`onAttach(context: CameraKPluginContext)`. The context has the holder's flows, `frames`,
`captures`, its own `scope` and `reportFailure`, and no commands. `launchPerSession { }` runs a
block per Ready session. See [Plugins](../guides/plugins.md#writing-a-plugin).
`CameraKEvent.PluginFailed(error: Throwable)` is now `PluginFailed(pluginId, error: CameraKError)`,
built only by CameraK; a thrown exception is `error.cause`.

## 11. Permissions

| 1.x | 2.0 |
|-----|-----|
| `providePermissions()`, `Permissions` | `rememberCameraKPermissionState(CameraKPermission.CAMERA, ...)` |
| `RequestCameraPermission`, `RequestMicrophonePermission`, `RequestStoragePermission` composables | `permissions.launchRequest()` from an event handler |
| `retry()` after a grant | nothing: the holder opens the camera on the next resume |

1.x prompted as a side effect of composition; 2.0 never prompts on its own. The holder checks the
camera permission before opening and reports `Error(Permission)`.

**iOS keys.** `NSCameraUsageDescription` always; `NSMicrophoneUsageDescription` only for a recording
with `enableAudio = true`; `NSPhotoLibraryAddUsageDescription` only for `MediaSaverPlugin`;
`NSPhotoLibraryUsageDescription` only for an app that calls `MediaSaverPlugin.readBytes`, which
fetches the asset by identifier and needs read access that the app requests itself.
**Android:** `RECORD_AUDIO` only with `enableAudio`; `WRITE_EXTERNAL_STORAGE` only with
`maxSdkVersion="28"`, which the saver's manifest already declares. **macOS:** a packaged desktop app
needs `NSCameraUsageDescription` in its bundle.

## 12. Lifecycle

- The camera stops in the background on every platform, and starts again in the foreground.
- `CameraKScreen(showPreview = false)` becomes using the holder without `CameraPreview`.
- A rotation keeps the holder and any recording.

## 13. Configuration

`CameraConfiguration` and `VideoConfiguration` are built with a DSL; the IDE's quick fix rewrites a
1.x named-argument call:

```kotlin
// 1.x
CameraConfiguration(cameraLens = CameraLens.BACK, flashMode = FlashMode.AUTO, targetResolution = 1920 to 1080)

// 2.0
CameraConfiguration {
    cameraLens = CameraLens.BACK
    flashMode = FlashMode.AUTO
    targetResolution = Resolution(1920, 1080)
}
```

- `copy(...)` becomes `copy { ... }`.
- `cameraLens` is nullable and defaults to null, the platform default camera.
- `directory` is gone (section 9); `outputDirectory` sets where files go.
- New fields: `cameraId`, `initialZoomRatio`, `targetOrientation`, `frameAnalysis`,
  `analysisResolution`, `analysisFormat`.
- The builders (`CameraControllerBuilder` and the platform builders) are gone: use the DSL.
- On desktop, `setGrabber(...)` and the `customGrabber` parameter become
  `CameraKPlatformContext(grabberFactory)`.

## 14. Testing your app

```kotlin
@Test
fun capturesAPhoto() = runTest {
    val fake = FakeCameraEngine()
    val holder = fakeCameraKStateHolder(fake = fake)
    holder.start()
    runCurrent()

    assertIs<CameraKResult.Success<CapturedImage>>(holder.capture())
}
```

`fakeCameraKStateHolder` needs no opt-in. Script the fake with `deliverOpen`, `failOpen`, `fail`,
`interrupt`, `reportTorch`, `reportZoom` and the rest, and build results with `FakeCaptures`.
`cameraKTestEnvironment()` and the holder's engine constructor are `@CameraKEngineApi`. If your
composables take core types, add `camerak`'s `compose-stability.conf` to your
`stabilityConfigurationFiles`: core types no longer carry `@Immutable` or `@Stable`. See
[Testing](../guides/testing.md).

## 15. Removed API

|---------|-------------|
| `CameraController` (every platform), its listeners, the engine bridge, `CameraKState.Ready.controller` | `CameraKStateHolder` |

| `captureImage()`, `toggleFlashMode()`, `toggleTorchMode()`, `toggleCameraLens()`, `shutdown()`, `getCameraCapabilities()` (hints) | `capture()`, `cycleFlashMode()`, `toggleTorch()`, `toggleLens()`, `close()`, `capabilities.value` |
| `rememberCameraKState` (hint) | `rememberCameraKStateHolder` |
| `CameraKScreen(cameraState, ...)` (hint) | `CameraKScreen(holder, ...)` |
| `CameraPreviewView`, `DefaultLoadingScreen`, `DefaultErrorScreen`, `LocalCameraKStateHolder` | `CameraPreview(holder)`, your own slots, the holder |
| `ImageCaptureResult`, `VideoCaptureResult` (hints) | `CameraKResult<CapturedImage>`, `CameraKResult<RecordedVideo>` |
| `ImageCaptureResult.Success(ByteArray)` | a capture is a file |
| `CameraConfiguration(...)`, `VideoConfiguration(...)` with named arguments (hints) | the DSL |
| `Directory` (kept only as the hint's parameter type) | `GalleryDestination` in `MediaSaverConfig` |
| `CameraKEvent.None`, `PermissionDenied`, `QRCodeScanned`, `TextRecognized`, `ImageCaptured`, `CaptureFailed`, `RecordingStarted`, `RecordingStopped`, `RecordingFailed`, `RecordingMaxDurationReached` | plugin `results`, `captures`, command results, `recordingState`, `RecordingEnded` |
| `CameraUIState.lastError`, `zoomLevel`, `maxZoom`, `isRecording`, `isPaused`, `recordingDurationMs`, `imageFormat`, `qualityPrioritization` | section 6 |
| `CameraCapabilities`' one-argument constructor; `LensInfo`'s constructor now needs `@CameraKEngineApi`, and `LensInfo` is not a data class | read them from `holder.capabilities` |
| `Rotation`, `InvalidConfigurationException` | `DeviceOrientation`, `CameraKError.Unsupported` |
| `Permissions`, `providePermissions()`, `RequestCameraPermission`, `RequestStoragePermission`, `RequestMicrophonePermission` | `rememberCameraKPermissionState` |
| `VideoRecorderPlugin`, `rememberVideoRecorderPlugin` | the holder's recording commands |
| `ImageSaverConfig`, `ImageSaveResult`, `saveImage`, `save(ByteArray, name)`, `readBytes(path)`; `getByteArrayFrom` (hint) | `MediaSaverConfig`, `SavedImage`, `save(image)`, `readBytes(saved)` |
| `ScannerHandle`, `RecognitionHandle`, `AnalyzerHandle`, `getQrCodeFlow`, `textFlow`, `ocrFlow`, `getAnalyzerFlow`, `extractTextFromBitmap`, `attachToStateHolder`, `startScanning`, `startRecognition`, `startAnalyzer` and the plugins' scope constructors | section 10 |
| `CameraControllerBuilder`, the platform builder factories, `DesktopCameraControllerBuilder.setGrabber`, the desktop `customGrabber` | the DSL, `CameraKPlatformContext(grabberFactory)` |
| Desktop `CameraGrabber`: its constructor, `start(scope, customGrabber)`, `setHorizontalFlip`, `stop`; `grabCurrentFrame()` (hint) | `CameraKPlatformContext(grabberFactory)`, `holder.capture()` |
| Desktop `ImagePanel`, `ImageCaptureManager` | `CameraPreview(holder)`, `holder.capture()` |
| Desktop `FrameConverter` (with `convert(Frame)` and `legacyHeld`), `OperatingSystem` | `holder.frames` |
| Android `MemoryManager`; iOS `MemoryManager` and `BurstCaptureManager` (removed with no deprecation release) | nothing; CameraK did not use them |
| Android `getActivityOrNull`, `Bitmap.compressToByteArray`, `ImageProxy.toByteArray` | nothing |
| iOS `NSData.toUIImage`, `UIImage.fixOrientation`, `UIImage.toByteArray` | nothing; `ByteArray.toNSData` and `NSData.toByteArray` stay behind `@InternalCameraKApi` |

### Closed and open types

A closed type gains a subtype or entry only in a major release, so a `when` over it can be exhaustive:
`CameraKState`, `CameraKError`, `CameraKResult`, `RecordingState`, `RecordingEndReason`,
`PermissionStatus`, `PluginStatus`, `CameraKPermission`, `ImageFormat`, `FrameFormat`. An open type
can grow in a minor release, so a `when` over it needs an `else`: `CameraKEvent` and the value
vocabularies `CameraFeature`, `CameraOperation`, `InterruptionReason`, `StorageFailure`,
`BarcodeFormat` and `OcrLevel`.

### From Swift

The holder is an ordinary class in the framework your shared module builds. Its commands are
suspend functions, which Swift sees as `async` functions. Its flows are Kotlin `StateFlow`s, which
Swift cannot observe directly: expose what a SwiftUI view needs from your shared module, for
instance a function that collects `cameraState` and calls a Swift closure, or use a bridge such as
SKIE. The 1.x hints are not meant for Swift: their names are gone in 2.1.
